# v1.0.2 流程图单图模式「顶部被遮挡」修复

> 日期：2026-11-05 ｜ 版本：1.0.2 ｜ 触发：用户反馈「流程图放大后，把窗口最大化，顶部被挡住一部分，看不到完整流程图」

## 根因（防御性覆盖两类）

1. **flex 居中 + 溢出裁顶**：单图模式容器 `.tm-map-scroll` 使用 `display:flex; align-items:center`。当 SVG 因浏览器缩放/取整/宽高比变化渲染高度略大于容器时，`align-items:center` 会把顶部溢出到不可滚动区域，`overflow:auto` 无法向上滚 → 顶部被裁。
2. **滚动位置残留**：容器 `overflow:auto`，切换模式/窗口尺寸变化前若有 `scrollTop>0`，放大后顶部仍在视口外。

## 修复

- 单图（flow）容器改为 **`display:block; overflow:hidden`**（顶部对齐，不再居中裁顶）；SVG `display:block; width:100%; height:auto; max-height:100%` —— 放得下时行为不变，比例不匹配时 SVG 内部 `preserveAspectRatio` letterbox，**顶部永远可见**。
- `TaskFlowInner` 新增 `resetMapScroll()`：进入 flow 单图、window resize、stretch relayout 后把 `.tm-map-scroll.scrollTop` 归零（非单图模式不影响）。
- `stretchFlowLayout(baseFlow, targetHeight, maxViewport)` 增加**容器二次 clamp**：目标 viewBox 高度 `min(target, 容器高 × flow.width / 容器宽)`，避免取整误差造成纵向溢出。
- 面板头底部 padding 7→10px，首行卡片徽标/子节点小字不再贴边。

## 验证（隔离实例 E2E，25 checks / 0 failed）

- 场景：小窗口 1200×760 进 flow 单图 → resize 到 2560×1440（模拟最大化）→ 恢复双栏 → 再放大；
- 断言：`display=block`、`overflow=hidden`、`scrollTop=0`、`SVG top ≥ 面板头 bottom-2`、`SVG bottom ≤ 面板 bottom+2`、首末行卡片完整可见、根视图不超宿主、无 console error；
- 12 尺寸矩阵（1024×700 ~ 3440×1440）全部「完整可见/不裁顶」；
- 证据：`docs/v102-e2e-verification.json`、`docs/v102-flow-max.png`（2560×1440 最大化后完整流程图）、`docs/v102-flow-small.png`（小窗口单图）；
- 测试：`client-smoke` 618 checks / `client-logic` 315 checks 全绿。

## 说明

无法在隔离环境复现用户原始故障（12 种尺寸均正常），本修复覆盖「flex 居中裁顶」与「滚动残留」两类最常见成因；如用户环境仍有问题，需要截图 + 屏幕分辨率/缩放（devicePixelRatio）进一步定位（例如横向裁切或面板头遮挡属不同成因）。
